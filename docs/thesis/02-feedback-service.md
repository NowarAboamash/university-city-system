# خدمة الشكاوى والمقترحات — FeedbackService

> قناة تواصل رسمية بين الطالب وإدارة المدينة الجامعية: يقدّم الطالب شكوى أو مقترحًا (مع صور اختيارية)، وتراجعه الإدارة وتردّ عليه، فيصل الطالب إشعارٌ بالردّ.

---

## 1. نظرة عامة

### 1.1 الغرض

توفير آلية منظّمة لاستقبال ملاحظات الطلاب (شكوى/مقترح)، وتتبّع حالتها (مقروءة/غير مقروءة)، والردّ الإداري عليها، مع دعم إرفاق صور وإخفاء هوية المُرسِل اختياريًا.

### 1.2 الموقع في المعمارية

| الخاصية | القيمة |
|---|---|
| التقنية | ASP.NET Core (.NET 9)، EF Core، SQL Server |
| المنفذ المحلي | `5069` (خلف البوابة `5067`) |
| قاعدة البيانات | `FeedbackServiceDb` (مستقلة) |
| المسارات الجذرية | `/api/feedbacks`، `/api/feedbackimages` |
| الاعتماديات الخارجية | AuthService (بحث أسماء المستخدمين)، NotificationService (إشعار الردّ)، Cloudinary (تخزين الصور) |

---

## 2. النموذج البرمجي وعلاقات الجداول

### 2.1 الجداول

| الجدول | الوصف | المفتاح |
|---|---|---|
| `Feedback` | شكوى أو مقترح لطالب: النوع، العنوان، النص، إخفاء الهوية، حالة القراءة، الردّ الإداري | `Id` (int، تسلسلي) |
| `FeedbackImages` | صورة مرفقة بشكوى: مسار الصورة (Cloudinary URL) | `Id` (int، تسلسلي) |

### 2.2 الحقول

**Feedback:**
| الحقل | النوع | ملاحظات |
|---|---|---|
| `StudentId` | `nvarchar(64)` | معرّف الطالب من مطالبة `sub` (Mongo ObjectId، نصّي لا رقمي). لا يُقبل من العميل. |
| `Type` | enum `FeedbackType` | `Suggestion = 0`، `Complaint = 1` (يُخزَّن كـ int) |
| `Title` | `nvarchar(200)` | إلزامي |
| `Description` | `nvarchar(max)` | إلزامي |
| `IsAnonymous` | `bit` | افتراضي `false`؛ عند `true` لا يُعرض اسم المُرسِل حتى مع معرفة معرّفه داخليًا |
| `IsRead` | `bit` | افتراضي `false`؛ يعني «هل رآها موظّف» — يقلبها فقط عرض الإداري أو الردّ، لا مراجعة الطالب لطلبه |
| `CreatedAt` | `datetime2` | افتراضي `GETUTCDATE()`؛ يُجبَر `Kind=Utc` عند القراءة كي يخرج التسلسل بصيغة UTC واضحة |
| `AdminReply` | `nvarchar(max)?` | نص الردّ الإداري |
| `RepliedByAdminId` | `nvarchar(64)?` | معرّف الإداري الذي ردّ |
| `RepliedAt` | `datetime2?` | تاريخ الردّ |

**FeedbackImage:** `ImagePath` (`nvarchar(500)`، إلزامي — رابط Cloudinary مطلق)، `FeedbackId` (FK).

### 2.3 العلاقات

```
Feedback 1───∞ FeedbackImage        (FK = FeedbackId، OnDelete = Cascade)
```

- علاقة واحدة فقط: شكوى واحدة ⇐ عدّة صور. حذف الشكوى يشلّل صورها في قاعدة البيانات، وتُحذف ملفاتها من Cloudinary صراحةً في طبقة الخدمة.
- `StudentId` و`RepliedByAdminId` مراجع منطقية لمستخدمين في AuthService (لا مفتاح أجنبي فعلي — قواعد بيانات مستقلة).

## 3. قواعد العمل (Business Rules)

| # | القاعدة |
|---|---|
| BR‑F1 | كل نقاط النهاية تتطلّب رمز JWT صالحًا. |
| BR‑F2 | `StudentId` يُشتقّ دائمًا من مطالبة `sub`؛ أي `studentId` في الجسم يُتجاهَل. |
| BR‑F3 | **الطالب يملك CRUD كاملًا مقيّدًا بشكاواه فقط:** إنشاء، سرد، عرض، تعديل، حذف — لكن فقط حيث `Feedback.StudentId == sub`. لمس شكوى غيره ⇒ `403 Forbidden`. |
| BR‑F4 | `admin` / `super_admin` وصول غير مقيّد: `GET /api/feedbacks` يُعيد كل السجلات، ويمكنهم عرض/تعديل/حذف أي شكوى. |
| BR‑F5 | `GET /api/feedbacks` يُصفّي تلقائيًا حسب الدور: للطالب على شكاواه، وللإداري بلا تصفية. |
| BR‑F6 | `GET /api/feedbacks/mine` يُعيد دائمًا شكاوى المستدعي فقط (لأي دور)، مُصفَّحة. |
| BR‑F7 | `IsRead` يُقلَب إلى `true` فقط حين يعرض إداري الشكوى (`GET /{id}` بدور إداري) أو حين يردّ عليها — لا عند مراجعة الطالب لشكواه. |
| BR‑F8 | الردّ (`POST /api/feedbacks/{id}/reply`) **للإداري فقط**؛ يضبط `AdminReply` و`RepliedByAdminId` (من الرمز) و`RepliedAt`، ويقلب `IsRead = true`، **ويُطلق إشعارًا للطالب** «تم الرد على شكواك». |
| BR‑F9 | إنشاء شكوى مع صور (`POST /api/feedbacks/with-images`) يجري ضمن **معاملة (Transaction)** مع استراتيجية إعادة المحاولة: إذا فشلت أي صورة تحقّقًا أو رفعًا، تُلغى المعاملة وتُنظَّف الصور المرفوعة مسبقًا. |
| BR‑F10 | تحقّق الصور: غير فارغة، ≤ 5 ميغابايت، الامتدادات المسموحة `.jpg`، `.jpeg`، `.png`، `.webp` فقط. |
| BR‑F11 | حذف الشكوى يشلّل صورها في قاعدة البيانات ويحذف ملفاتها من Cloudinary. |
| BR‑F12 | حذف صورة مفردة (`DELETE /api/feedbackimages/{id}` و`/by-path`) **للإداري فقط**؛ الطالب ينظّف صوره بحذف الشكوى الأمّ (تشليل). |
| BR‑F13 | في `GET /api/feedbacks` يُملأ `studentName` و`repliedByAdminName` من AuthService عبر **نداء دفعي واحد لكل صفحة** (كل المعرّفات الفريدة)، لا نداء لكل عنصر. |
| BR‑F14 | `studentName` يبقى `null` للشكاوى مجهولة الهوية حتى لو كان `studentId` معروفًا داخليًا — الإخفاء يُطبَّق وقت العرض. |
| BR‑F15 | فشل AuthService لا يُسقط الطلب — تعود الأسماء `null` فقط (تصميم «لا يرمي استثناء»). |

## 4. حالات الاستخدام (Use Cases)

### UC‑01 تقديم شكوى/مقترح (بدون صور)
- **الفاعل:** الطالب.
- **المسار:** `POST /api/feedbacks` بـ `{Type, Title, Description, IsAnonymous}` ← يُشتقّ `StudentId` من الرمز ← إنشاء السجل بحالة `IsRead = false`.
- **ما بعد:** شكوى جديدة في طابور الإدارة.

### UC‑02 تقديم شكوى مع صور
- **الفاعل:** الطالب.
- **المسار:** `POST /api/feedbacks/with-images` (multipart) بالبيانات + قائمة صور ← بدء معاملة ← حفظ الشكوى ← لكل صورة: تحقّق ثم رفع إلى Cloudinary ثم سطر `FeedbackImage` ← تثبيت المعاملة.
- **استثناء:** فشل أي صورة ⇒ إلغاء المعاملة + تنظيف ما رُفع + `400`.

### UC‑03 عرض الطالب لشكاواه
- **الفاعل:** الطالب.
- **المسارات:** `GET /api/feedbacks` (يُصفّى تلقائيًا) أو `GET /api/feedbacks/mine` (مُصفَّح) أو `GET /api/feedbacks/{id}` (يتحقّق من الملكيّة، لا يقلب `IsRead`).

### UC‑04 مراجعة الإدارة لشكوى
- **الفاعل:** الإداري.
- **المسار:** `GET /api/feedbacks` (كل السجلات، مُصفَّحة، بالأسماء) ← `GET /api/feedbacks/{id}` ⇒ يقلب `IsRead = true`.

### UC‑05 الردّ على شكوى
- **الفاعل:** الإداري.
- **المسار:** `POST /api/feedbacks/{id}/reply` بـ `{Reply}` ← ضبط حقول الردّ + `IsRead = true` ← **إشعار الطالب**.
- **ما بعد:** الطالب يرى الردّ ويتلقّى إشعارًا في صندوق الوارد.

### UC‑06 تعديل / حذف شكوى
- **الفاعل:** الطالب (لشكواه) أو الإداري (لأي شكوى).
- **المسارات:** `PUT /api/feedbacks/{id}` — `DELETE /api/feedbacks/{id}` (يتحقّق من الملكيّة لغير الإداري ⇒ `403` عند الخرق).

### UC‑07 إدارة الصور
- `GET /api/feedbackimages/feedback/{feedbackId}` — صور شكوى.
- `POST /api/feedbackimages/upload` — رفع صورة لشكوى قائمة.
- `DELETE /api/feedbackimages/{id}` أو `/by-path?fileNameOrPath=` — حذف صورة (إداري فقط).

## 5. مرجع نقاط النهاية (API)

| الطريقة والمسار | الدور | الوظيفة |
|---|---|---|
| `GET /api/feedbacks` | Any | قائمة مُصفَّحة (طالب: شكاواه؛ إداري: الكل + الأسماء) |
| `GET /api/feedbacks/mine` | Any | شكاوى المستدعي، مُصفَّحة |
| `GET /api/feedbacks/{id}` | Any (بملكيّة) | تفصيل شكوى (يقلب `IsRead` للإداري فقط) |
| `POST /api/feedbacks` | Any | إنشاء شكوى/مقترح |
| `POST /api/feedbacks/with-images` | Any | إنشاء مع صور (معاملة) |
| `PUT /api/feedbacks/{id}` | Any (بملكيّة) | تعديل شكوى |
| `POST /api/feedbacks/{id}/reply` | A | الردّ + إشعار الطالب |
| `DELETE /api/feedbacks/{id}` | Any (بملكيّة) | حذف شكوى (+ حذف صورها من Cloudinary) |
| `GET /api/feedbackimages/feedback/{feedbackId}` | Any | صور شكوى |
| `POST /api/feedbackimages/upload` | Any | رفع صورة لشكوى |
| `POST /api/feedbackimages` | Any | إضافة سطر صورة بمسار جاهز |
| `DELETE /api/feedbackimages/{id}` | A | حذف صورة بالمعرّف |
| `DELETE /api/feedbackimages/by-path` | A | حذف صورة بالمسار/الاسم |

المعاملات: `pageNumber` (افتراضي 1)، `pageSize` (افتراضي 10، بين 1 و50). شكل الاستجابة المُصفَّحة موحّد: `{ items, pageNumber, pageSize, totalCount, totalPages }`.

## 6. التكامل مع الخدمات الأخرى

| الوجهة | الآلية | الاستخدام |
|---|---|---|
| **NotificationService** | `INotificationPublisher.NotifyUserAsync` (لا يرمي استثناء) | إشعار الطالب عند الردّ على شكواه. |
| **AuthService** | `IUserLookupService` (نداء دفعي، مفتاح داخلي) | ملء `studentName` / `repliedByAdminName` في قائمة الشكاوى فقط. |
| **Cloudinary** | `IImageUploader` عبر `FileHandler` | رفع/حذف صور الشكاوى في مجلد `feedback`؛ روابط `https` مطلقة. |

---

## 7. الأمان والصلاحيات

- تحقّق JWT محلي (RS256) على مستوى الـ Controller كله (`[Authorize]`).
- تمييز الدور بدالة `IsAdmin()` (`User.IsInRole("admin") || "super_admin"`).
- تحقّق الملكيّة بدالة `OwnsFeedback()` (`feedback.StudentId == sub`) قبل أي تعديل/حذف/عرض من غير إداري.
- حذف الصور المفردة محصور بالإداري.
- روابط الصور روابط Cloudinary عامّة مطلقة — لا تُمرَّر عبر البوابة ولا تُسبَق بأصل الخدمة.

## 8. قرارات تصميمية (للأطروحة)

| القرار | المبرّر |
|---|---|
| `StudentId` نصّي (`nvarchar(64)`) لا رقمي | `sub` في AuthService هو Mongo ObjectId، لا عدد صحيح. |
| عدم قبول `studentId` من العميل | منع انتحال الهوية؛ المصدر الوحيد الموثوق هو الرمز. |
| `IsRead` يقلبه الإداري فقط | الحقل يعني «هل رآها موظّف»؛ مراجعة الطالب لشكواه لا يجب أن تُخفيها عن الإدارة. |
| إخفاء الهوية عند العرض لا بإخفاء المعرّف | يبقى `StudentId` مخزّنًا للتدقيق الداخلي، بينما `studentName` لا يُملأ للمجهولة. |
| نداء أسماء دفعي واحد لكل صفحة | تفادي مشكلة N+1؛ نداء واحد لكل الأسماء الفريدة في الصفحة. |
| المعاملة + التنظيف في الإنشاء مع الصور | ضمان الذرّية: إمّا شكوى بكامل صورها أو لا شيء، بلا ملفات يتيمة على Cloudinary. |
| تخزين على Cloudinary بدل القرص المحلي | تعمل الصور عبر خدمات مستضافة مستقلًا بلا توجيه بوابة. |
| فشل التكامل الخارجي لا يُسقط الطلب | الردّ ينجح حتى لو تعذّر الإشعار؛ القائمة تنجح حتى لو تعذّرت الأسماء. |

---

## 9. القيود والأعمال المستقبلية

- إثراء الأسماء (`studentName` / `repliedByAdminName`) موجود في قائمة الشكاوى فقط، لا في `GET /{id}` ولا `/mine`.
- لا تصنيف/توسيم للشكاوى ولا حالة «قيد المعالجة» منفصلة عن «مقروءة».
- صفوف أُنشئت قبل الانتقال إلى Cloudinary قد تحمل مسارات محلية قديمة (`/uploads/...`) لن تُحلّ.
